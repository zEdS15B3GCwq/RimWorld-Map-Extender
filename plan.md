# Map Extender: plan and progress

Goal: enlarge an existing colony map offline by rewriting the save. Pad the map on any side (W/E/S/N), shift every cell reference, then fill the new border with content copied from a donor map generated by the game.

Environment and rules are in [CLAUDE.md](CLAUDE.md). This file tracks the plan, findings and status.

## Phases

### 0. Setup + round trip ✅
- `mapext/savefile.py`: lxml loader, plus a writer that mimics .NET XmlWriter (BOM, CRLF, tabs, `<x />`, `&gt;` escaping, CRLF in text).
- `python -m mapext roundtrip include/2.rws out/2_roundtrip.rws` → byte-identical (load 0.2 s, write 1.3 s).
- Known limitation: whitespace-only text is dropped by the parser (`remove_blank_text`). The sample save has none; the roundtrip command would report it.

### 1. Coordinate census ✅
`python -m mapext census include/2.rws out/census.md` scans the whole save for coordinate-like values (IntVec3, `IntVec3, Map_N` targets, CellRect, IntVec2, Vector3), per-cell grids (base64 blobs, one-`<li>`-per-cell lists), BoolGrid sizes and suspicious ints. It groups them by normalized path and labels each group with the first matching rule in `mapext/census.py: RULES`:
- `shift`: add the pad offset to x/z.
- `shift-if-map`: world-level value pointing into a map; shift when that map is the one being extended.
- `grid`: pad a per-cell array.
- `size`: replace with the new map size.
- `keep`: not a position on the extended map.
- `unknown`: anything unmatched. Blocks the extender until a rule is added.

Path normalization: `game/maps/li` → `MAP`; every thing (element with `<def>` + `<id>`) at any depth restarts the path at `THING`, so things inside containers, caskets or pawns' inventories share one row.

The rule table is the Phase 3 spec. Per-map defaults to "shift", so new mod IntVec3 fields on a map are handled automatically; world-level values default to `unknown`.

### 2. Grid codecs + rendering ✅
`mapext/grids.py`, `mapext/render.py`; CLI `python -m mapext grids include/2.rws --render out/render`.
- Format (`DataExposeUtility.LookByteArray`): raw Deflate (.NET `DeflateStream`, no zlib header; Python `zlib` with `wbits=-15`) → base64 → wrapped at 100 chars, with a line break before and after → `<labelDeflate>`. If deflating doesn't shrink the data, plain base64 goes in `<label>`. `GridRef.store()` renames the element when that choice changes.
- Cell layout is inferred from the decoded length: `N*k` bytes = k-byte little-endian cells (u16 terrain/roof/snow/sand/deep resources/temperature/compressed things, u32 gas, 8 B river flow); `ceil(N/8)` bytes = bit-packed bools, LSB first (BoolGrid areas/pollution/Helixien, fog).
- Python's deflate output is ~10% smaller than the game's, so the base64 text differs. The check is on the decoded bytes: decode → array → bytes → encode → decode must equal the original. **All 72 grids pass.**
- Renders: one PNG per grid per map plus `things.png` (thing positions by category), north up. In Map_0, terrain, things, rock (compressed thing map) and roofs line up with each other.
- `find_grids(map)` finds grids by decoding any blob whose size fits the map's cell count; `find_cell_lists(map)` finds the `<li>`-per-cell lists (MixedBiome).

### 3. Padding only ✅
`mapext/pad.py`; CLI: see `extend` below (originally a `pad` command).
- The census walk is now a reusable generator (`census.iter_values`). `pad_save` classifies every value with `census.RULES` first and aborts on any `unknown` path before changing anything. Then:
  - size: `mapInfo/size`, BoolGrid `mapSizeX`/`mapSizeZ`;
  - grids: terrain `topGrid`/`underGrid` and `temperatureCache` are padded by copying the edge; every other grid gets 0 (none/False). MixedBiome `<li>` list: edge copy;
  - shift: every value on a padded map, skipping `(-1000, -1000, -1000)`. CellRect shifts both corners. Vector3 keeps y and writes x/z as float32 with 9 significant digits, like the game;
  - shift-if-map: history look targets by their `Map_N`; quest part cells by the part's `mapParent` (world object → `mapInfo/parent`) or a `map*` field naming a pawn (→ the map holding it); `cameraMap/camRootPos` when `currentMapIndex` is padded. Unresolvable valid values are reported and left alone (none in the sample saves).
- Linked maps: only the chosen map and its MultiFloors levels change. Levels are read from the ground map's `MF_LevelMapComp/mapByLevel`, so choosing Map_25 also pads Map_0. They get identical padding and must be the same size. Checked by comparing map subtrees: with `--map Map_0`, Map_23 is unchanged; with `--map Map_23`, Map_0 and Map_25 are unchanged. The sample saves have no quest maps, but they'd be treated the same way. The DeepRim map (Map_23) is untouched: `holeLocation` is an underground cell, and the lift on Map_0 is an ordinary shifted thing.
- `verify_pad` (runs after every `extend` unless `--no-verify`) re-reads the output and checks: new sizes; every grid cropped back equals the original; every coordinate value equals the original or the original + offset, exactly where the rules say.
- Results: pad 0 → value-identical to the input (only grid compression differs). Pads of 1, 25 (325×325), W3/S5 and, on the plans save, E10/N20 all verify; census on the 325×325 output has 0 unknown and 0 out-of-bounds values. 52k IntVec3, 3 Vector3, 18 world-level targets, 44 size fields, 51 grids + 1 cell list per run.
- In-game test (user): `pad0`, `pad25`, `pad_w3s5` and `2pc_pad_e10n20` load with no new errors (the original save's errors remain); `pad1` not tried. Padding is on the right sides at the right width, including the MultiFloors level. Pawns walk into the border and haul items there. Buildings, pawns, plans and blueprints are in the right spots. The border shows stripes and no fog, as expected.

### Map selection and `extend` ✅ (confirmed in game)
- `python -m mapext maps <save>` (`mapext/maps.py`) lists maps per tile as a tree of recorded links, with each map's padding group. The user picks from it.
- `python -m mapext extend <in> <out> --map ID [--map ID ...] [--all N | --west/--east/--south/--north N]` replaces the `pad` command. `--map` is required and repeatable. One set of padding applies to every chosen map; per-map sizes aren't supported (decided with the user), since runs are fast and can be chained.
- Choosing any MultiFloors level pads its whole group, and two choices in one group count once. DeepRim maps change only when chosen, or when a level built on them is chosen.
- `holeLocation` now shifts when its DeepRim map is padded (`shift-if-map`, resolved through the world object). A DeepRim world object with no map is left alone.
- `verify_pad` also checks that every unselected map's subtree is unchanged.
- Offline results on `2_2colonies_MFDRmix.rws`: `--map Map_0 --map Map_25 --map Map_27` (two groups, E10/N20), `--map Map_26` (W5/S4) and `--map Map_28` (all 10) all verify. Pad 0 on `2.rws` stays value-identical. Test saves: `out/mix_0_23_e10n20.rws`, `out/mix_26_w5s4.rws`, `out/mix_28_all10.rws`.
- In game (user): all three test saves load with no new errors, with the right maps padded by the right sizes and the others unchanged. Shafts, lifts and stairs line up, and MultiFloors levels stay connected, including padded DeepRim maps.

### 4a. Nearest-edge fill ✅ built (not loaded in game yet)
- `extend ... --fill edge|donor`, default `edge`, replacing today's partial fill.
- Copy from the nearest old edge cell: natural terrain, natural roofs (not `RoofConstructed`), river flow, fog, temperature, plain rock.
- Terrain: if `underGrid` is set, the top is a built floor, so use the under terrain as the new top. Don't copy `foundationGrid`. Fertility follows from terrain.
- `compressedThingMap` holds one thing per cell: rock, ores, chunks and others. Copy only the stone types; chunks become empty.
- Don't copy plants, animals, gas, snow, sand, pollution or deep resources. They come back in play or aren't wanted.
- Mined tunnels on the edge carry on into the border (accepted).
- Ore on the edge becomes a stone from its 8 neighbours if there is one, otherwise empty. Smoothed floors are copied as they are. Damaged or designated rock (saved as a normal thing, so absent from the grid) isn't handled, by decision.
- Def values are `shortHash`es, computed from def names (`pad._short_hashes`). The game bumps a hash up when it is taken, and that depends on the mod list (`MineableSteel` is one above its plain hash), so a few steps are accepted. Modded stones and ores need adding to `STONES`/`ORES`, or they stay empty.
- `verify_pad` checks border cells against the rules, using its own nearest-cell lookup.
- Test saves: `out/fill_0_all20.rws`, `out/fill_23_e10n20.rws`, `out/fill_26_w5s4.rws`, `out/fill_28_all10.rws`.
- Soil Relocation Framework is active in the samples and adds no grid or census path, so it needs nothing.

### Donor notes
- `--donor <save> --donor-map <id>`: both needed. Users generate donor saves themselves; we only give instructions.
- `maps` prints the world settings and each map's computed seed (not stored in the save, so unconfirmed against the game).
- Map seed: `HashCombineInt(StableStringHash(world seedString), tile)`, not dependent on size; pocket maps use the parent ID instead of the tile. Elevation noise is sampled at raw cell coordinates. Alignment still needs a test.

### 4. Donor content
The user generates donor saves with the same mod list. Copy terrain, grids and natural things (rock, ores, plants, filth) into the border; reassign thing IDs and bump `uniqueIDsManager`. Rock walls live in `compressedThingMapDeflate` (def `shortHash`; fine with the same mod list). Fog the new border.
- Hypothesis to test: map generation is anchored at the bottom-left, so a larger map on the same tile/seed lines up on the N/E edges but not S/W. Also look for the map seed in the save.
- Edge blending: low priority, later.

### 5. Polish
CLI `mapext extend ...`, refuse to run on `unknown` census paths, tests on small real save cuts.

### Coordinate system (from source)
- `IntVec3` = `(x, y, z)`, y is altitude (always 0). x = east, z = north, origin at the south-west corner. Saved as text `(12, 0, 34)`; map size as `(275, 1, 275)`.
- Cell index = `z * sizeX + x` (`CellIndicesUtility`). Grids are row-major from the south: reshape to `(sizeZ, sizeX)`.
- Shift for padding: `(x + padW, y, z + padS)`.
- Rock walls etc. are "save-compressible" and stored only in `compressedThingMapDeflate` as per-cell ushort def `shortHash` values (`MapFileCompressor`).

### Map types and links (verified on `include/2_2colonies_MFDRmix.rws`)
- Type: `mapInfo/parent` names a world object in `world/worldObjects` or `world/pocketMaps`. `Settlement` = colony when its faction's def equals `scenario/playerFaction/factionDef`; `DeepRim.UndergroundMapParent` has `depth`; MultiFloors levels are `PocketMap` with `MF_LevelMapComp/level`, and `sourceMap` on the world object.
- MultiFloors: `MF_LevelMapComp/groundMap` on every map, and `mapByLevel` on the ground map. Level 0 omits `level`. A DeepRim map can be a ground map.
- DeepRim: `DeepRim.UndergroundManager/layers` (depth → world object) and `layerNames` on whichever map holds the shaft, including a MultiFloors level. DeepRim maps vary in size (100×100, 150×150 here).
- Sharing a tile says nothing about links: all five maps on tile 127024 are connected, but through different kinds of link.
- Sample: Map_0 colony → { Map_25 MF -1 → Map_26 DeepRim "MF-DR1"; Map_23 DeepRim "COL-DR7" → Map_27 MF -1 }; Map_28 second colony on another tile. The outposts have no maps.
- Checks on this save: round trip byte-identical (71 MB), all grids round-trip, 0 unknown census paths. The only new census row is MixedBiome at 150×150. Padding each map verifies and leaves every map outside its group byte-identical in serialized form. Not loaded in the game yet.

## Census results (sample save)

295 path groups: size 17, grid 25, shift 51, shift-if-map 9, keep 193, **unknown 0**. Blobs are detected by the `*Deflate` tag name (the `LookByteArray` convention) as well as by length, because all-zero grids compress to a few dozen characters. The fog grid is all zeros (nothing fogged) on every map in this save. Full report: `out/census.md` (regenerate it with the command above).

### What has to change when padding a map
- **size**: `mapInfo/size`; every BoolGrid's `mapSizeX`/`mapSizeZ` (all `areaManager` areas' `innerGrid`, `pollutionGrid/grid`, Helixien `infiniteGasGrid`).
- **grid** (pad): `terrainGrid/{top,under,foundation,color,temp}GridDeflate`, `roofGrid/roofsDeflate`, `fogGrid`, `snowGrid`/`sandGrid/depthGridDeflate`, `gasGrid/gasDensityDeflate`, `pollutionGrid`, `deepResourceGrid/{def,count}GridDeflate`, `temperatureCache/temperaturesDeflate` (+ `vacuum`), `compressedThingMapDeflate`, area `innerGrid/arrDeflate`, `WaterInfo/riverFlowMapDeflate`, Helixien `infiniteGasGrid`, `MixedBiomeMapComponent/biomeGrid` (one `<li>True</li>` per cell).
- **shift** (all IntVec3/Vector3 under `MAP/`): thing `pos` (43k values, including things inside containers and pawns), pawn jobs/pather/duty/verb targets, zones' `cells`, designations, reservations, lords' defend spots, mine strikes, water bodies' `rootCell`, SomeThingsFloat cell lists, `rememberedCameraPos`.
  - Skip invalid `(-1000, -1000, -1000)` values.
  - Unused verb targets are `(0, 0, 0)`; shifting them is harmless.
- **shift-if-map** (world level):
  - `history/.../lookTargets`, in the form `(x, y, z), Map_N`.
  - Quest part cells: the map comes from the part's `mapParent` (a world object ID matching a map's `mapInfo/parent`), or else from `mapParentOfPawn` (the map holding that pawn).
  - `cameraMap/camRootPos`, when `currentMapIndex` is the extended map.
- **keep**:
  - stale `pos` of unspawned things (world pawns, outposts, trade stock, quest items);
  - world grids and features;
  - `world/info/initialMapSize`;
  - MultiFloors gravship `relativeCells` / `engineToCenter` (offsets);
  - body-part, toil and stage indices, graphic seeds and cycle counters.

### Source review notes
- Vanilla saves map cells only as IntVec3 text or whole-map grids, never as plain int indices. I checked every class that both scribes data and uses `CellToIndex`/`IndexToCell`.
- Mods decompiled into `include/Mods-decompiled/<Assembly>/`. Mod findings:
  - Adaptive Storage `Positions` (List<int>) are slot indices inside the storage building, not map cells.
  - ReGrowth SmartFarming keys are zone IDs.
  - DeepRim `holeLocation` is in underground-map coordinates.
  - MultiFloors stairs link by reference (`mf_entrance`); `StairEntrance` on Map_0 and `StairExit` on Map_25 sit on the same cell (182, 129), so the basement must get identical padding.
  - RimLogic and Rimatomics save IntVec3 fields (feedCell, destinationCell, ...). None appear in this save; on a map they are covered by the default shift rule. Rimatomics `WorldObject_Missile.destinationCell` would show up as world-level `unknown`.
- Second sample `include/2_plans_constructions.rws` (same colony, plus plans and build blueprints): round trip byte-identical, all grids round-trip, 0 unknown paths. The only new census row is `MAP/planManager/allPlans/li/cells/li` (IntVec3 list, `shift`; `Plan.ExposeData` saves just ID/label/color/cells). Blueprints (`Blueprint_Build`, `Blueprint_Door`) are ordinary things carrying only `pos`, so they're covered by the thing `pos` rule. Every other difference is pawn activity between the two saves.
- Still not in any sample save:
  - `Map.landingBlockers`: a `List<CellRect>` that Odyssey orbital and space maps use to block gravship landing. It falls under the `MAP/` shift rule. Phase 3 has to shift both corners of a CellRect: `(minX+W,minZ+S,maxX+W,maxZ+S)`.
  - Temporary terrain (ice from freezing, floods, lava): it lives in `terrainGrid/tempGridDeflate`, which is already padded as a grid.

### Grid findings from Phase 3
- `WaterInfo.riverFlowMap` (2 floats per cell) is indexed `x * sizeZ + z`, unlike every other grid. On a square map the size check can't tell; `GridRef` now transposes it (`grids.X_MAJOR_LABELS`). The padded render matches the river terrain.
- `temperatureCache/temperatures` is per cell (room temperature written into each of the room's cells). Padded by edge copy.
- Fog is padded with 0 (unfogged); the sample saves have no fog. Phase 4 should fog the border.
- Terrain edge copy makes stripes in the border (water and roads stretch outward). It's a placeholder until donor content.
